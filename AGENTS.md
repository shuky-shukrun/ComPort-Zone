# ComPort Zone Agent Guide

## Project Shape

ComPort Zone is a Windows-first COM-port terminal for device bring-up, debugging, and repeated engineering command workflows. It is a Python 3.12+ desktop app built with PySide6, pyserial, PyInstaller `onedir`, and an Inno Setup installer.

Use this file as the canonical project guide for coding agents. Tool-specific files should stay thin and point back here.

## Start Here

- For any code change, start with `docs/LLM_CHANGE_GUIDE.md`.
- For architecture context, read `docs/ARCHITECTURE.md`.
- For deeper design and data/control flows, read `docs/DESIGN.md`.
- For executable behavior examples, inspect the closest `tests/test_*.py` file before editing.

## Standard Commands

Set up a fresh clone:

```powershell
.\setup_dev.bat
```

Launch the app:

```powershell
.\launch_app.bat
```

Run all tests:

```powershell
.\run_tests.bat
```

Run a focused test:

```powershell
.\scripts\run_tests.ps1 tests.test_quick_actions
.\scripts\run_tests.ps1 tests.test_app_sessions.AppSessionTests.test_rename_tab_updates_title
```

Build the Windows package:

```powershell
.\build_exe.bat
```

Check whitespace before handing off changes:

```powershell
git diff --check
```

## Testing Rules

- The repo uses `unittest` through the included batch and PowerShell scripts. Do not introduce pytest-only instructions unless the project changes.
- Use focused tests for the touched subsystem, then run the full suite for code changes.
- Qt widget tests should follow existing `QApplication.instance() or QApplication([])` patterns.
- Do not assume physical COM hardware is available. Use existing fakes, adapters, or test seams.

## Change Guardrails

- Avoid generated or local output directories such as `.venv`, `build`, `dist`, `release`, `__pycache__`, and test/cache artifacts.
- Preserve app settings JSON, quick command CSV, and quick file CSV compatibility unless a task explicitly changes those formats.
- Keep pure domain/service modules free of Qt widget dependencies.
- Prefer controllers and services for behavior decisions; widgets should mostly apply UI state and presentation.
- Keep `src/ComPort_Zone/app.py` compatible with older imports and tests that use `ComPort_Zone.app.MainWindow`.
- Do not hand-edit `.codex/environments/environment.toml`; it is autogenerated by the owning tool.
- Do not commit local secrets, provider keys, or runtime `.env` files.

## Tool Notes

- Continue, Copilot, and other assistant-specific files are adapters. They should point to this guide and the docs above instead of duplicating large ownership maps.
- If a tool needs project commands, use the commands in this file and keep them aligned with `README.md`, CI, and `docs/LLM_CHANGE_GUIDE.md`.
